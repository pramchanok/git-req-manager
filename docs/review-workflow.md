# Review workflow and sync reliability

- Dashboard filters support projects, labels, drafts, known successful CI and MRs unchanged for more than two days. Named filters are saved on this device per GitLab installation and user. Unknown pipeline states do not match the CI filter.
- Notifications are retained in an account-specific inbox (latest 200 entries, up to 10 accounts). Quiet hours use the computer's local clock; equal start/end times disable the quiet period. Muting an MR for an hour/day suppresses its desktop popups while keeping new events in the inbox; it does not schedule a reminder. Test Notification bypasses quiet hours.
- MR comment drafts are saved while typing and cleared only after a successful post. Drafts, Viewed paths and resume positions use installation/user/project/MR-specific local storage keys. A changed head SHA invalidates Viewed checks conservatively for all files. Drafts/review state contain local plaintext content, not access tokens.
- The comment composer opens with the Markdown toolbar by default; its editor bundle loads when the composer mounts. The smile icon loads the emoji picker on demand. Hidden MR windows pause their periodic refreshes and catch up when visible; request bursts are coalesced and note events are filtered to the matching MR.
- Sync requests received during a cycle schedule a subsequent cycle. Webhook mode reconciles at least every configured interval, with a minimum interval of five minutes. MR/pipeline webhooks invalidate only the matching pipeline cache entry (global MR ID takes precedence over project/IID); missing identity falls back to project or whole-cache invalidation. Note events preserve pipeline caches. Invalidated in-flight responses cannot refill the cache. Results from an old account are discarded and its detail/report windows close when credentials change.
- Partial API failures preserve the previous section snapshot. Sync Health distinguishes the last attempt, last fully successful sync, per-section successful timestamps and last webhook received. A selected project's failed fetch makes All Open a failed section rather than presenting an incomplete collection as current.
- Tokens are encrypted with the OS store when secure storage is available. Otherwise they remain in memory until exit. Legacy Base64 tokens migrate to encrypted or session storage on access. Linux `basic_text` is treated as insecure. Settings shows session-only storage status.

## Verification

`npm run build` runs unit tests, TypeScript checks for both processes, renderer bundling and main compilation. Mocked browser checks can validate renderer interactions without contacting GitLab. Live relay delivery, OS notifications/keychain and packaged app behavior require verification in their target environments.
